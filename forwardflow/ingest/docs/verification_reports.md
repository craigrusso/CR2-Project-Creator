# Verification Report System

## Overview

The ForwardFlow ingest system now includes comprehensive verification reporting that generates detailed reports for every transfer job, documenting the verification status of each file copied.

## Features

### Report Generation
- **Dual Format Output**: Both human-readable TXT and machine-readable CSV formats
- **Per-Job Reports**: Unique report files generated for each transfer job
- **Comprehensive Coverage**: Reports generated for all verification modes (FAST, BALANCED, STREAM_VERIFY, READBACK_VERIFY, NONE)
- **Performance Optimized**: Asynchronous report writing that doesn't impact copy performance

### Report Location
- Reports are saved in a `_ForwardFlow_Reports` subfolder alongside each destination root folder
- File naming format: `verify_report_YYYY-MM-DD_HHMM.txt` and `verify_report_YYYY-MM-DD_HHMM.csv`
- Example: `_ForwardFlow_Reports/verify_report_2025-08-22_1530.txt`

### Report Contents
Each report contains one row per file with the following information:
- **File name**: Name of the copied file
- **Source path**: Full path to source file
- **Destination path**: Full path to destination file  
- **File size**: Size in bytes
- **Hash type**: Verification hash algorithm used (xxHash64, MD5, SHA256, or "Size-Only")
- **Source hash**: Hash value calculated from source file
- **Destination hash**: Hash value calculated from destination file
- **Status**: Verification result (PASS or FAIL)
- **Timestamp**: When verification was completed
- **Error message**: Details if verification failed

### Report Formats

#### TXT Format (Human-Readable)
```
ForwardFlow Verification Report
Job ID: ingest_20250822_1530
Generated: 2025-08-22 15:30:45

=== VERIFICATION SUMMARY ===
Total Files: 150
Passed: 150
Failed: 0
Success Rate: 100.0%

=== FILE DETAILS ===

File: video001.mov
Source: /source/videos/video001.mov
Destination: /backup/videos/video001.mov
Size: 2,147,483,648 bytes (2.0 GB)
Hash Type: xxHash64
Source Hash: a1b2c3d4e5f6789a
Destination Hash: a1b2c3d4e5f6789a
Status: PASS
Verified: 2025-08-22 15:32:10
```

#### CSV Format (Machine-Readable)
```
filename,source_path,destination_path,file_size_bytes,hash_type,source_hash,destination_hash,status,timestamp,error_message
video001.mov,/source/videos/video001.mov,/backup/videos/video001.mov,2147483648,xxHash64,a1b2c3d4e5f6789a,a1b2c3d4e5f6789a,PASS,2025-08-22 15:32:10,
```

## Configuration

### UI Control
A "Generate Verification Report" checkbox is available in the ingest tab settings:
- **Default**: Enabled (reports generated by default)
- **Behavior**: Checkbox is disabled during transfer and re-enabled upon completion
- **Location**: Settings section of the ingest tab

### Programmatic Control
```python
from forwardflow.ingest.api.models import JobOptions

# Enable verification reports (default)
options = JobOptions(generate_verification_report=True)

# Disable verification reports
options = JobOptions(generate_verification_report=False)
```

## Implementation Details

### Engine Integration
- **Python Engine**: Uses `VerificationReportManager` class for thread-safe report management
- **C++ Engine**: Native C++ implementation with `VerificationRecord` structs and direct file I/O
- **Performance**: Report writing is asynchronous and doesn't block the copy process

### Verification Modes
- **STREAM_VERIFY**: Real-time hash verification during copy
- **READBACK_VERIFY**: Post-copy verification by reading destination files
- **BALANCED**: xxHash64 verification for speed/accuracy balance
- **FAST**: Size-only verification
- **NONE**: No verification (still creates "PASS" records for copied files)

### Error Handling
- Report writing failures emit `report.failed` events but don't cancel transfers
- Graceful fallback if report directory cannot be created
- Thread-safe operation with proper error isolation

## Technical Architecture

### Data Flow
1. **Record Creation**: Each file verification creates a `VerificationRecord`
2. **Collection**: Records are stored in memory during the job
3. **Finalization**: At job completion, all records are written to disk
4. **Formatting**: Concurrent TXT and CSV file generation

### File Structure
```
destination_folder/
├── copied_files/
└── _ForwardFlow_Reports/
    ├── verify_report_2025-08-22_1530.txt
    └── verify_report_2025-08-22_1530.csv
```

### Performance Characteristics
- **Memory Usage**: Minimal - records stored as lightweight structs
- **I/O Impact**: Report writing happens after copy completion
- **Scalability**: Handles large file lists efficiently through streaming I/O
- **Concurrency**: Thread-safe record collection and writing

================================================================================
WHAT WAS BROKEN
================================================================================

Symptom #1: Second transfer starts → empty report appears immediately
Symptom #2: Second cancel → no report generated at all

Root Cause:
- Rust engine uses SINGLETON pattern (persists across transfers)
- Event queue NOT cleared between transfers
- Stale DestCompleted events from cancelled transfer fire on next start
- CRITICAL TYPO: Called drain_all() instead of drain_all_events()
  → Queue never actually drained!
- No validation to reject stale events

================================================================================
WHAT WAS FIXED
================================================================================

Fix #1: Reset Engine State
- Call engine.reset() before each transfer
- Clears cancelled flags, job_id, progress tracker

Fix #2: Drain Event Queue (CORRECT METHOD)
- Call queue_handle.drain_all_events() (not drain_all!)
- Removes ALL stale events before starting new transfer
- Prevents premature DestCompleted events

Fix #3: Guard Against Stale Events
- Check transfer_worker exists and is valid
- Check transfer_thread is actually running
- Verify destination matches current job
- Return early if event is stale

Fix #4: Path Normalization
- Normalize destination paths for reliable matching
- Handle trailing slashes, case sensitivity, symlinks
